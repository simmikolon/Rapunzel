# Sir Bouncealot for iOS

A thin native shell: one full-screen `WKWebView` showing `../web` straight
from the app bundle. The game itself is the browser game; nothing here
changes gameplay. The page and the shell talk through `web/src/platform.js`
(see `docs/PORTING.md` for the contract).

What the shell adds over Safari:

- The game loads from the bundle through a custom URL scheme
  (`app://game/`), so it works offline and the ES modules get a proper origin.
- Tilt steering from CoreMotion: no permission prompt, same dead zone and
  full-tilt angle as in the browser.
- Best height, effects preset and mute live in `UserDefaults`.
- Light haptics on bonk, stomp, hit and game over.
- The ring/silent switch mutes the game; music from another app keeps
  playing (ambient audio session).
- The screen never dims while steering by tilt; the game pauses when the
  app resigns active (Control Centre, a call, the lock screen).
- The safe-area insets (Dynamic Island, home indicator) go to the page with
  the saved state, so the HUD keeps clear of them while the picture fills
  the whole screen.

## Build and run

Open `ios/SirBouncealot.xcodeproj` in Xcode (26.3 or newer), pick your
iPhone and press Run. The project references `../web` as a folder, so the
checkout you have is what runs on the phone: switch branches, press Run.

From the command line (Simulator):

```sh
cd ios
xcodebuild -project SirBouncealot.xcodeproj -scheme SirBouncealot \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

The project file is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml` (`brew install xcodegen`). After editing `project.yml`
run `xcodegen generate` in `ios/` and commit the regenerated project with
it. `App/Info.plist` is written by XcodeGen too; edit `project.yml`, not
the plist. Version and build number live in `Version.xcconfig`, which needs
no regeneration: bump `CURRENT_PROJECT_VERSION` before every upload.

## Development helpers

Debug builds read two launch arguments (Product > Scheme > Edit Scheme >
Arguments, or `xcrun simctl launch booted com.simonkemper.sirbouncealot ...`):

- `-gameQuery "at=150&spawn=squirrel&dev=1"`: appended to the page URL, so
  every helper from `web/src/dev.js` and `?fx=` works on the device.
- `-gameEval "<javascript>"`: run once the page has loaded, for driving the
  game from a script (`window.game.startRound()`, for example).

Debug builds are inspectable from Safari (Develop menu). Page errors and
the bridge's complaints go to the system log under the bundle id:

```sh
xcrun simctl spawn booted log stream --predicate 'subsystem == "com.simonkemper.sirbouncealot"'
```

Saved values sit in the app's container, not in the global defaults domain:

```sh
plutil -p "$(xcrun simctl get_app_container booted com.simonkemper.sirbouncealot data)/Library/Preferences/com.simonkemper.sirbouncealot.plist"
```

## TestFlight

1. App Store Connect: create the app record for `com.simonkemper.sirbouncealot`
   (name "Sir Bouncealot") and an internal testing group.
2. Xcode: destination "Any iOS Device (arm64)", Product > Archive,
   Distribute App > TestFlight Internal Only, upload.
3. Next upload: bump `CURRENT_PROJECT_VERSION` in `Version.xcconfig`.

Export compliance is answered in the Info.plist (no non-exempt encryption)
and `PrivacyInfo.xcprivacy` declares the one required-reason API
(UserDefaults), so neither blocks the build in review.

## App icon

`App/Assets.xcassets/AppIcon.appiconset/icon-1024.png` is made from the web
icon with `python3 tools/app_icon.py` (a 2x nearest-neighbour upscale,
alpha dropped as the store requires).
